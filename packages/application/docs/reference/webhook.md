# Webhooks

An organization sends `scan.succeeded`, `scan.failed` and `finding.created` to its own
endpoints or to a Slack channel. Managing webhooks needs `organization.webhook.manage`
(owner, admin). A webhook can cover every project, or one.

## What is stored

The URL and the signing secret are encrypted with `SecretCipher`. A Slack incoming-webhook
URL is a credential on its own: anyone holding it can post to the channel. The list shows a
hint (`hooks.slack.com/…a1b2`), and nothing reads the URL back to a person. A generic
webhook's secret is generated by the server (`whsec_…`) and shown once, when it is created.
A Slack webhook has no secret, because Slack verifies nothing.

## From an event to a delivery

`WebhookSubscriber` reads the tenant's webhooks when one of the three events comes off the
outbox. It queues one job on `QueueName.WEBHOOK` per webhook that is on, wants the event,
and covers the event's project. The job id is `<event>-<webhook>`, so a redelivered event
queues nothing new. Each job retries on its own (8 attempts). One dead endpoint then never
holds back another, nor the event's other subscribers.

`DeliverWebhookUseCase` sends the job and records the answer in one statement. A success
resets the failure count. A failure adds one, and at 20 in a row it sets `disabled_at`.
While the webhook is still on, a failure throws, which is the queue's retry. Once the
webhook is off, the job ends quietly. Turning it back on clears the count. **Send test**
calls the same send and answers at once, without touching the count.

## The request

```
POST <url>
content-type: application/json
x-wiremap-event: scan.failed
x-wiremap-delivery: <event id, the same on every retry>
x-wiremap-timestamp: <unix seconds>
x-wiremap-signature: sha256=<hex HMAC-SHA256 of "<timestamp>.<body>" with the secret>
```

A receiver checks the signature against the raw body and refuses an old timestamp. It
deduplicates on `x-wiremap-delivery`. A generic body is the event as published, plus the
project's name and a link. A Slack body is Block Kit with a text fallback, with `<`, `>`
and `&` escaped.

## The address guard

The request leaves from inside our network to a URL a customer typed, so
`FetchWebhookSender` does four things:
- it sends to https only;
- it resolves the host, and refuses it unless **every** address is public (no loopback,
  private, link-local, carrier-NAT or multicast range, IPv4 or IPv6);
- it follows no redirect;
- it gives up after ten seconds.

A refused send counts as a failure with no status.

One gap remains: `fetch` resolves the name again, so a host that answers DNS differently on
the second lookup could still reach an inside address. Closing it means pinning the checked
address into the connection. That is noted for the security review (`WM12.1`).
